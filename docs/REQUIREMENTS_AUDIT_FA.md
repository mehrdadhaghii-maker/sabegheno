# گزارش بررسی خط‌به‌خط نیازمندی‌های Pasted_content.txt

## نتیجهٔ اجرایی

هر سه پروژهٔ موجود شامل ۶۹ فایل متنی/منبعی اسکن شدند: بک‌اند Node/Express/Prisma، فرانت‌اند React/Vite و پنل ادمین React/Vite. تغییرات اصلی در همان فایل‌های اصلی اعمال شد و پروژهٔ جداگانه یا کپی اجرایی ساخته نشد.

## اولویت ۱ — رفع باگ‌های منطقی

| بند | وضعیت | تغییر انجام‌شده |
|---|---|---|
| ۱.۱ تأیید کسب‌وکار | انجام شد | فیلد پایدار `Business.isVerified` اضافه شد؛ ادمین هنگام تأیید آن را `true` و هنگام تعلیق/بازگشت به مدارک آن را `false` می‌کند. middleware این مقدار را همراه status بررسی می‌کند. endpoint `GET /auth/me` نیز وضعیت تازه را برمی‌گرداند تا بعد از تأیید، کاربر با refresh یا تغییر نشست وضعیت قدیمی نبیند. seed برای کسب‌وکارهای approved قبلی backfill انجام می‌دهد. |
| ۱.۲ تسویه و بدحسابی | انجام شد | سرویس stacking اکنون eventهای تعهد، تسویه و بدحسابی را با ترتیب زمانی جمع‌بندی می‌کند و مبلغ تسویه‌شده را از تعهد باز کم می‌کند. تعهد تسویه‌شده دیگر به‌عنوان تعهد فعال شمرده نمی‌شود. وضعیت `settled_with_bad_debt` نیز در خروجی scoring قرار گرفت. |
| ۱.۳ سایز موبایل در دسکتاپ | اصلاح شد | هیچ state موبایل hard-coded در کد پیدا نشد؛ layout با media query کنترل می‌شود. برای remount صحیح صفحات و جلوگیری از باقی‌ماندن layout قبلی، صفحهٔ جاری با `key` مستقل و transition کنترل می‌شود و عرض‌ها fluid باقی مانده‌اند. |
| ۱.۴ navigation | اصلاح شد | علاوه بر state قبلی، مسیر صفحه با hash مرورگر sync می‌شود، `popstate` پشتیبانی می‌شود و screen هنگام تغییر مسیر remount می‌شود. رفرش مرورگر روی صفحهٔ کسب‌وکار همان screen را بازسازی می‌کند. |

## اولویت ۲ — UI و گزارش‌ها

- صفحهٔ ورود کسب‌وکار با logo SVG واقعی سابقه‌نو، شعار، فونت Vazirmatn، ورودی‌های بزرگ‌تر، طراحی دو ستونه، gradient و حالت responsive حفظ و تکمیل شد.
- پنل ادمین logo واقعی، title و favicon برند دارد.
- چرخهٔ سلامت اعتباری با SVG، animation انتقالی و رنگ‌های brand نمایش داده می‌شود.
- dashboardهای فرانت‌اند و ادمین نمودارهای Recharts را از دادهٔ API استفاده می‌کنند؛ دادهٔ ساختگی جدید به نمودارها اضافه نشده است.
- تاریخچهٔ استعلام‌ها فیلتر متن، وضعیت و بازهٔ تاریخ دارد.
- خروجی CSV برای ردیف‌های فیلترشده اضافه شد. خروجی PDF از مسیر چاپ مرورگر انجام می‌شود تا وابسته به سرویس PDF خارجی نباشد.
- پنل ادمین بازهٔ تحلیل روزانه، ماهانه و سالانه دارد و API ادمین نیز `period=day|month|year` را پشتیبانی می‌کند.
- اعداد فارسی/خوانا و فونت‌های بزرگ‌تر در CSS سراسری اعمال شده‌اند.
- کد ملی در دیتابیس به‌صورت hash ذخیره می‌شود؛ بنابراین خروجی عمداً کد ملی خام را افشا نمی‌کند و export فقط شناسهٔ محافظت‌شده را نشان می‌دهد.

## اولویت ۳ — قابلیت‌های جدید

| بند | وضعیت | توضیح |
|---|---|---|
| ۳.۱ مدارک، قرارداد و فاکتور | نیازمند فاز مستقل | status و contractSigned در مدل فعلی وجود داشت و workflow تأیید ادمین فعال است؛ اما storage واقعی مدارک، صدور قرارداد حقوقی و billing نیازمند تصمیم محصول، فضای ذخیره‌سازی و درگاه/حسابداری است و بدون آن‌ها نباید به‌صورت نمایشی یا fake پیاده‌سازی شود. |
| ۳.۲ سطوح معوقات | انجام شد با محدودیت دادهٔ API | adapter تسهیلات سطح جاری/سررسیدگذشته/معوق/مشکوک‌الوصول را از تعداد اقساطی که provider برمی‌گرداند محاسبه می‌کند و در گزارش نشان می‌دهد. اگر API فقط مبلغ aggregate برگرداند، سطح دقیق به‌عنوان دادهٔ در دسترس provider محدود می‌ماند. |
| ۳.۳ API شرکت‌های دیگر | زیرساخت موجود، توسعهٔ اتصال واقعی نیازمند قرارداد | Providerها، eventها و API گزارش‌دهی موجودند. برای هر شرکت خارجی باید API key، قرارداد payload، rate limit و webhook مشخص شود؛ ساخت credential آزمایشی بدون این اطلاعات ایمن نیست. |
| ۳.۴ درون‌ریزی بدحسابان | انجام شد | فایل CSV با ستون‌های `nationalId,eventType,amount,delayDays,note` در UI خوانده و حداکثر ۱۰۰۰ ردیف معتبر به endpoint تراکنشی `/providers/report/bulk` ارسال می‌شود. |
| ۳.۵ PDF | انجام شد به‌صورت print/PDF | دکمهٔ PDF/چاپ تاریخچه از print stylesheet استفاده می‌کند و کاربر می‌تواند Save as PDF بگیرد. |
| ۳.۶ پنل مدیریت کسب‌وکار | بخشی انجام شد | صف کسب‌وکارها، status، contractSigned موجود بود و approval به Provider خودکار متصل است. مدارک و توضیح رد/تعلیق برای فاز بعدی به storage و مدل توضیحات نیاز دارد. |
| ۳.۷ سیاست اعتباری | انجام شد | PolicyRule، API و پنل سیاست وجود دارد و scoring آن را می‌خواند. |
| ۳.۸ لوگو در title bar | انجام شد | favicon و title برند در هر دو index و لوگو در header/login قرار گرفت. |

## تست نهایی

- `prisma generate`: موفق.
- `prisma validate` با `DATABASE_URL` نمونه: موفق.
- syntax check تمام فایل‌های JS بک‌اند: موفق.
- `GET /api/health`: پاسخ `status: ok`.
- build فرانت‌اند Vite: موفق.
- build پنل ادمین Vite: موفق.
- تست اتصال واقعی PostgreSQL/API.ir در این sandbox انجام نشد، چون credential و سرویس Postgres واقعی در محیط بررسی موجود نبود. برای آن باید روی سرور شما `docker compose up -d --build` اجرا و لاگ API بررسی شود.
