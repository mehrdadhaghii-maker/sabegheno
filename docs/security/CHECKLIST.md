# چک‌لیست امنیت سامانه — با ستون «گزارش»

**راهنمای وضعیت:** ✅ انجام شد و بررسی شد · ⚠️ انجام شد با انحراف/ناقص (توضیح در گزارش) · ⏳ باید شما اجرا کنید
**تاریخ ثبت:** ۱۴۰۵/۰۷/۱۷ (۹ اکتبر ۲۰۲۶)

> **مهم:** «بررسی شد» یعنی کد را خواندم و منطق‌ها را با دیتابیس ساختگی در حافظه تست کردم (۲۸ بررسی نشست و پاک‌سازی + بردار رسمی TOTP + تست‌های رمز و کارت). **هیچ‌چیز روی Postgres و سرور واقعی اجرا نشده**؛ بعد از `npx prisma db push` یک دور تست دستی لازم است (بخش «تست پذیرش» پایین).

## ۱. AUTH — چک ورود و خروج
| وضعیت | مورد | گزارش |
|---|---|---|
| ✅ | قفل اکانت بعد از ۵ بار رمز اشتباه (۴۸ ساعت) | ادمین: شمارنده اتمیک، قفل ۴۸ ساعته، رد حتی با رمز درست، پیام دقیق طبق فایل، HTTP 423. منطق `lockDecision` تست شد. ورود با OTP: قفل ۴۸ ساعته **عمداً** نیست (ریسک مسدودکردن حساب دیگران) — جایگزین: ۵ حدس برای هر کد |
| ✅ | بستن سشن بعد از ۳۰ دقیقه بی‌فعالیتی | تست حافظه: ۳۱ دقیقه ⇒ بسته؛ ۲۹ دقیقه ⇒ باز. پولینگ پس‌زمینه فعالیت حساب نمی‌شود |
| ✅ | بستن سشن قبلی با ورود جدید | تست حافظه: همیشه فقط ۱ نشست فعال؛ نشست قدیمی `SESSION_REPLACED` می‌گیرد |
| ✅ | JWT ۱۵ دقیقه‌ای + Refresh Token چرخشی | Refresh Token فقط به‌صورت هش ذخیره می‌شود؛ توکن قدیمی بعد از چرخش مرده است |
| ✅ | خروج دستی از پنل | هر دو پنل: خروج در سرور هم نشست را می‌بندد؛ «بستن همهٔ نشست‌ها» |
| ⚠️ | ورود با «ایمیل + رمز» (auth.md) | سامانه ایمیل ندارد: ادمین = نام کاربری + رمز، کسب‌وکار/کاربر = موبایل + OTP |

## ۲. HACK — تست نفوذ
| وضعیت | مورد | گزارش |
|---|---|---|
| ✅ | SQL Injection (Prisma) | هیچ query خام در پروژه نیست |
| ✅ | XSS (React) | هیچ `dangerouslySetInnerHTML`؛ گزارش PDF با escape؛ CSP با `script-src 'self'` |
| ⚠️ | CSRF | Bearer header (نه کوکی) ⇒ CSRF کلاسیک ممکن نیست؛ توکن CSRF اضافه نشد؛ محافظ Content-Type اضافه شد |
| ✅ | Authentication Bypass | ۶۸ route بررسی شد؛ **یک نقص رفع شد** (`/utils/*` برای نقش کاربر عادی باز بود). اجرای `npm run audit:routes` بعد از نصب توصیه می‌شود |
| ✅ | Rate Limiting فعال | ۱۰۰/۱۵دقیقه روی auth؛ ۱۰/۱۰دقیقه روی OTP/ورود ادمین؛ IP واقعی پشت nginx اصلاح شد |
| ✅ | Security Headers (helmet) | helmet + nginx + HSTS؛ CORS محدود به `CORS_ORIGINS` |
| ⏳ | `npm audit` — بدون vulnerability | اینترنت نداشتم؛ دستور در HACK.md |
| ⏳ | OWASP ZAP / Burp | دستور در HACK.md |

## تست پذیرش (بعد از اجرا — ۱۰ دقیقه)
1. `npx prisma db push` و بالا آوردن سرور؛ ورود ادمین؛ باز شدن «مانیتورینگ» و «امنیت».
2. ۶ بار رمز غلط ادمین ⇒ پیام قفل (۴۲۳) ⇒ `npm run auth:unlock -- admin`.
3. ورود ادمین در دو مرورگر ⇒ مرورگر اول در درخواست بعدی با «نشست قبلی بسته شد» خارج شود.
4. ۳۱ دقیقه بدون کار ⇒ خروج خودکار با پیام بی‌فعالیتی.
5. فعال‌سازی 2FA، خروج و ورود با کد.
6. در پنل کسب‌وکار «حساب من» ⇒ حذف حساب ⇒ شمارهٔ موبایل آزاد و ثبت‌نام دوباره ممکن.
7. `npm run retention:run` ⇒ ردیف جدید در «گزارش پاک‌سازی».
8. ایجاد یک خطا (مثلاً قطع موقت دیتابیس) ⇒ ظهور در مانیتورینگ و (اگر ربات تنظیم شد) در تلگرام.
