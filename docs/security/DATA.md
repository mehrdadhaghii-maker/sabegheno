# مستند ۳ — DATA (پاک‌سازی داده‌های حساس)

## هدف
نگه نداشتن داده‌های شخصی بیش از نیاز: شمارهٔ موبایل، ایمیل و کارت بانکی.

## قوانین دقیق
| # | قانون |
|---|---|
| ۱ | کاربر حساب خود را حذف کند ⇒ **داده‌های شخصی فوراً پاک** می‌شود (و ردیف حساب «حذف نرم» می‌شود: `deletedAt`) |
| ۲ | **۳۰ روز** پس از درخواست حذف ⇒ **حذف سخت** (ردیف از دیتابیس برداشته می‌شود) |
| ۳ | حساب **بیش از ۱۲ ماه غیرفعال** ⇒ حذف خودکار (همین مسیر ۱ و ۲) |
| ۴ | **شمارهٔ کارت بانکی هرگز ذخیره نمی‌شود**؛ فقط توکن درگاه + ۴ رقم آخر |
| ۵ | پس از هر پاک‌سازی، **گزارش تعداد رکوردهای حذف‌شده** ثبت شود |

## روش پیاده‌سازی
- **تعریف «فوراً پاک»** (`src/services/dataRetention.service.js` → `softDeleteBusiness` / `softDeleteUser`):
  - کسب‌وکار: شمارهٔ موبایل با `deleted-<id>` جایگزین، نام و لوگو پاک، دلیل رد پاک، پیام‌های پشتیبانی و اعلان‌ها حذف، کدهای OTP حذف، همهٔ نشست‌ها بسته. حساب `suspended` می‌شود.
  - کاربر عادی: موبایل و هش کد ملی جایگزین، توکن‌های کارت حذف، نشست‌ها بسته.
  - شمارهٔ موبایل بلافاصله آزاد می‌شود؛ می‌توان دوباره ثبت‌نام کرد.
- **حذف سخت** (`hardDeleteBusiness` / `hardDeleteUser`): استعلام‌ها، لاگ استعلام‌ها، قوانین سفارشی، نشست‌ها و خود ردیف حذف می‌شود. سابقهٔ مشترک Providerها می‌ماند و فقط پیوندش به این کسب‌وکار قطع می‌شود.
- **Cron:** `src/cron/dataRetention.js` — هر شب **۰۳:۳۰ به وقت تهران**. همان Job خانه‌تکانی هم می‌کند: OTPهای منقضی (>۱ روز)، نشست‌های قدیمی (>۳۰ روز)، تلاش‌های ورود (>۹۰ روز).
- **API:** `DELETE /auth/account` با بدنهٔ `{"confirm":"حذف"}` (UI: «حساب من» در پنل کسب‌وکار، «حذف حساب» در گزارش کاربر).
- **کارت بانکی:** مدل `PaymentCard` فقط `token` و `last4` دارد. اکنون هیچ بخشی کارت نمی‌گیرد. محافظ: هر عدد ۱۳ تا ۱۹ رقمی معتبر (Luhn) در متن تیکت‌های پشتیبانی و لاگ‌ها به `**** **** **** 1234` تبدیل می‌شود (`src/utils/pan.js`).
- **ایمیل:** سامانه ایمیل ذخیره نمی‌کند.
- پارامترها در env: `HARD_DELETE_AFTER_DAYS=30`، `INACTIVE_ACCOUNT_MONTHS=12`.

### نکات تصمیم
- **حذف خودکار حساب غیرفعال، بدون هشدار قبلی** اجرا می‌شود (مطابق متن فایل). پیشنهاد: ۳۰ روز قبل یک پیامک/اعلان هشدار بفرستید.
- بدهکارهای ثبت‌شده توسط یک کسب‌وکار (`Defaulter`) پس از حذف آن کسب‌وکار **باقی می‌مانند** (برای حفظ ایمنی شبکه)؛ مدیر می‌تواند از پنل «بدحسابان» آنها را تسویه کند.
- پشتیبان‌های دیتابیس (backup) داده‌های قدیمی را دارند؛ دورهٔ نگه‌داری پشتیبان را با همین قاعده هماهنگ کنید.

## گزارش‌گیری
- جدول `cleanup_reports`: هر اجرا یک ردیف (نوع، تعداد کل، جزئیات هر بخش) و یک لاگ 🧹.
- **پنل ادمین → امنیت → «گزارش پاک‌سازی داده‌ها»** + دکمهٔ «اجرای دستی». روی سرور: `npm run retention:run`.
