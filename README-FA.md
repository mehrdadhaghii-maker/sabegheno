# سابقه‌نو — نسخهٔ یکپارچه (v18 — ناتمام در بخش رابط کاربری)

یک پروژهٔ کامل با سه بخش:

| پوشه | توضیح | پورت dev |
|---|---|---|
| `backend/` | Node.js + Express + Prisma + PostgreSQL | 4000 |
| `frontend/` | اپ کسب‌وکار / کاربر (همان فرانت v12 + داشبورد جدید) | 5173 |

## تغییرات این نسخه
**داشبورد ادمین (جدید):** KPI با مقایسه با بازهٔ قبل و sparkline، نمودار روند تصمیم‌ها و امتیاز، ترکیب تصمیم‌ها، هشدارهای هم‌پوشانی (anti-stacking)، صف تأیید کسب‌وکارها، سلامت Providerها، توزیع امتیاز، فعال‌ترین کسب‌وکارها، رویدادهای Provider؛ صفحات کسب‌وکارها (جستجو، تب‌ها، Drawer جزئیات)، استعلام‌ها (فیلتر، صفحه‌بندی، CSV، جزئیات)، منابع داده (ایجاد/ویرایش/اتصال) و سیاست اعتبار (اسلایدر + پیش‌نمایش اثر). ریسپانسیو با منوی موبایل، کلید Esc و دسترس‌پذیری صفحه‌کلید.

**داشبورد کسب‌وکار (ارتقا):** انتخاب بازهٔ ۷/۳۰/۹۰ روز، ۵ KPI، نمودار ستونیِ انباشتهٔ روزانه، توزیع امتیاز، هشدارهای هم‌پوشانی.

**بک‌اند:** `GET /admin/analytics?days=`، `GET /credit-checks/stats?days=`، ذخیرهٔ snapshot منابع در هر استعلام (رفع باگ «از دست رفتن جزئیات در تاریخچه»)، اسکریپت دادهٔ نمایشی `npm run seed:demo`.

## v14 — اصلاحات و ماژول‌های جدید (طبق فایل sabegheno-fix-prompt)

**بک‌اند (نیازمند `npx prisma db push`):**
- **باگ هم‌پوشانی (بحرانی) — رفع شد.** دو علت داشت: (۱) استعلام یک کسب‌وکار هیچ‌جا برای دیگران دیده نمی‌شد، چون فقط رویدادهای Provider بررسی می‌شد؛ (۲) آستانه «حداقل ۲ منبع» بود، پس دو کسب‌وکار هرگز هشدار نمی‌گرفتند. حالا هر استعلام *قبل از* تماس با سرویس‌های کُند در `InquiryLog` ثبت می‌شود (دو استعلام هم‌زمان همدیگر را می‌بینند)، آستانه در سیاست اعتبار قابل تنظیم است (پیش‌فرض: یک کسب‌وکار دیگر) و استعلام‌های قبلیِ کسب‌وکار اول هم برچسب هشدار می‌گیرند.
- **بدحسابان:** ثبت «بدحسابی/چک برگشتی» فرد را در کل شبکه مسدود می‌کند (رد قطعی در استعلام همهٔ کسب‌وکارها)، تا زمانی که همان کسب‌وکار «تسویه + رفع بدحسابی» ثبت کند.
- **کسب‌وکار:** رد با دلیل (فیلد قابل ویرایش)، تأیید/تعلیق/رد، آپلود لوگو (فقط PNG/JPG/WebP با بررسی محتوای واقعی فایل؛ SVG عمداً ممنوع)، اعلان خودکار تغییر وضعیت.
- **سیاست اعتبار:** تنظیمات تفصیلی + قوانین سفارشی «اگر … آنگاه …» سراسری یا ویژهٔ یک کسب‌وکار.
- **سرویس‌های خارجی:** اتصال دستی سرویس وب با کلید (رمزنگاری AES‑256‑GCM، هرگز به مرورگر برنمی‌گردد)، تست زنده، نمایش نتیجه در جزئیات استعلام/گزارش PDF و قابل استفاده در قوانین سیاست.
- **پشتیبانی** (تیکت دوطرفه) و **اعلان‌ها** (ارسال از ادمین → زنگ با شمارندهٔ خوانده‌نشده در پنل کسب‌وکار).

**ادمین:** منوی بالا (بدون همبرگر/X)، هدر با لوگوی بی‌کادر، کارت‌های گرادیانی با سایه و هاور، KPI درشت، جداسازی هزارگان در کل پروژه، فونت واحد Vazirmatn (محلی، بدون وابستگی به Google Fonts)، صفحهٔ استعلام‌ها با نمودار دونات کل + تفکیک هر کسب‌وکار، لوگوی کسب‌وکارها در نمای کلی و نقشهٔ منابع داده، صفحات پشتیبانی و اعلان‌ها.

**کسب‌وکار:** هدر و منوی بالا، داشبورد با دونات «جریان تصمیم»، فرم استعلام جدید تفصیلی (اعتبارسنجی کد ملی، ورودی مبلغ با جداکننده)، صفحهٔ یکپارچهٔ «تعهدات و بدحسابان»، تاریخچه با فیلتر + **PDF/چاپ هر گزارش**، پشتیبانی و سؤالات متداول در منو (بعد از تاریخچه)، زنگ اعلان، توست‌های مدرن.

**ورود/ثبت‌نام (هر دو پنل):** طرح Aurora دو ستونه با اعتبارسنجی، حالت‌های بارگذاری و خطا؛ ثبت‌نام کسب‌وکار ۳ مرحله‌ای (اطلاعات → OTP → لوگو).

### توضیحات صادقانه
- **اجرا نشده:** `npm install`/`build` و دیتابیس واقعی در محیط من ممکن نبود. فقط syntax همهٔ فایل‌ها، منطق هم‌پوشانی (با Prisma ساختگی)، و چیدمان CSS (رندر در مرورگر) بررسی شد. ابتدا `npx prisma db push` و بعد build را اجرا کنید.
- **ویدیوی ورود:** فایل برند ندارم. `auth-hero.mp4` را در `public/` هر دو اپ بگذارید؛ تا آن موقع پس‌زمینهٔ متحرک شفق نمایش داده می‌شود.
- **PDF:** از چاپ مرورگر (گزینهٔ «ذخیره به‌صورت PDF») استفاده می‌شود تا فونت فارسی درست جاسازی شود؛ تولید PDF سمت سرور اضافه نشد.
- **تکنولوژی طرح Aurora:** مطابق پروژهٔ موجود با React + Tailwind v3/CSS و `motion` پیاده شد (نه Tailwind v4 / App.tsx). دکمه‌های Google/GitHub چون ورود پروژه OTP موبایلی است با انتخاب «کسب‌وکار / گزارش شخصی» جایگزین شد.
- **سرویس‌های خارجی:** اتصال‌دهنده فرض می‌کند پاسخ JSON است و عدد در یک مسیر مشخص (مثلاً `data.count`) قرار دارد. برای هر سرویس واقعی (تخلفات رانندگی، نقاط منفی) باید URL و مسیر پاسخ را مطابق مستندات همان سرویس وارد کنید.
- **Docker:** متغیر `ENCRYPTION_KEY` الزامی شد و volume لوگوها (`uploads_data`) اضافه شد. لوگوها از خود API روی مسیر `/uploads` سرو می‌شوند؛ پس `VITE_API_BASE_URL` در هر دو اپ باید به آدرس عمومی API اشاره کند (تغییری در nginx لازم نیست).
- ورود با موبایلِ ثبت‌نشده در حالت «ورود» (همان رفتار قبلی بک‌اند) به‌طور خودکار یک کسب‌وکار جدید با نام پیش‌فرض می‌سازد؛ بهتر است بعداً بین ورود و ثبت‌نام جدا شود.
- صفحهٔ «تصویر اعتباری» (CreditMap) قدیمی هنوز سرویس‌های خارجی را جدا نشان نمی‌دهد؛ این‌ها در جزئیات ادمین و PDF هستند.

## اجرای محلی
```bash
# 1) دیتابیس (PostgreSQL) و متغیرها
cd backend && cp .env.example .env     # DATABASE_URL را تنظیم کنید
npm install
npx prisma db push                      # ستون جدید sources ساخته می‌شود
npm run prisma:seed                     # ادمین: اگر ADMIN_DEFAULT_PASSWORD قوی نداده باشید، یک رمز تصادفی فقط همین یک بار چاپ می‌شود
npm run seed:demo                       # (اختیاری) داده نمایشی برای دیدن داشبوردها
npm run dev

# 2) فرانت‌ها (هرکدام در ترمینال جدا)
cd frontend && cp .env.example .env && npm install && npm run dev
cd admin    && cp .env.example .env && npm install && npm run dev
```
در حالت dev کد OTP در لاگ بک‌اند چاپ می‌شود (`[OTP-DEV-MODE]`). برای Docker: `docker-compose.production.yml` و `.env.production.example`.

## نکات مهم (صادقانه)
- **در محیط من npm به اینترنت دسترسی نداشت**، پس `npm install` و `vite build` اجرا نشد. همهٔ فایل‌های JS/JSX با esbuild از نظر syntax بررسی و منطق آنالیتیکس تست شد، اما اجرای کامل (build + اتصال به Postgres) را روی سیستم خودتان انجام دهید. اگر خطایی دیدید متنش را بفرستید تا رفع کنم.

## عیب‌یابی: پنل ادمین بالا نمی‌آید

0. اگر با Docker بالا می‌آورید و build فرانت/ادمین با خطای `npm ci … package-lock.json` تمام می‌شود: در این نسخه به `npm install` تغییر کرده است.

1. در پوشهٔ `admin` یک‌بار `npm install` بزنید (بستهٔ `motion` و `@fontsource/vazirmatn` جدید هستند)، سپس `npm run dev`.
2. در پوشهٔ `backend` حتماً `npx prisma db push` را اجرا کنید؛ بدون آن جدول‌های جدید وجود ندارند و بخشی از داده‌ها بارگذاری نمی‌شود (حالا پنل در این حالت بالا می‌آید و بالای صفحه پیام خطا نشان می‌دهد).
3. اگر صفحهٔ «خطا در نمایش صفحه» دیدید، متن آن را بفرستید. اگر صفحه کاملاً سفید بود، Console مرورگر (F12) را باز کنید و خطای قرمز را بفرستید.
